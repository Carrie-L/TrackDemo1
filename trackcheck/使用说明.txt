埋点小岛 · 使用说明
====================

一、启动与退出（全程无黑框）
1. 把整个文件夹解压到任意位置（建议放在普通目录，如 D:\Tools\埋点小岛）。
2. 双击「埋点小岛.exe」，后台静默启动服务并自动打开浏览器（不再弹出黑色命令行窗口）。
   - 再次双击 exe：如果小岛已经在后台运行，会直接帮你打开浏览器页面，不会重复启动。
   - 查看日志：点击网页右上角的「运行日志」按钮，随时查看运行状态与异常堆栈；有异常时会自动亮起提示。
   - 退出服务：点击网页右上角「休息」→「安心退出服务」，即可干净关闭后台进程并释放端口。
3. 你的数据全部保存在 exe 旁边的「埋点小岛数据」文件夹里：
     埋点小岛数据\trackcheck.yaml   测试用例、点位规则、模板、字典映射、数据源配置
     埋点小岛数据\datasources\      从手机拉的数据库、抓到的接口 JSON（.history 里是历史版本）
     埋点小岛数据\event_dict.json  导入的埋点字典；docs\ 里是埋点文档原文
     埋点小岛数据\reports\          校验报告、抓包日志、运行日志（server.log）
   - 网页「导入 / 分享」页最上面的「我的数据都在这里」会显示这个文件夹的位置和数量，点一下就能打开。
   - 第一次打开时文件夹里已经带好了一份规则 / 用例 / 字典，打开就能用；之后你的所有修改都只保存在这里。
   - 备份 / 换电脑：复制整个「埋点小岛数据」文件夹，放到 exe 旁边即可。
   - 移动程序时记得连这个文件夹一起移；只拷 exe 的话，你的数据不会跟过去。
   - 升级新版本：先在网页右上角点「休息」退出，用新 exe 替换旧 exe，「埋点小岛数据」文件夹保留不动即可。

二、手机 / adb
- 需要 adb。装过 Android Studio 的电脑会自动找到（PATH、ANDROID_HOME、%LOCALAPPDATA%\Android\Sdk）。
- 没装的话：把 Google 官方的 platform-tools 文件夹放到 exe 同目录（埋点小岛\platform-tools\adb.exe）即可。
- 手机打开 USB 调试并连上电脑，右上角显示绿色设备名就是连上了。

三、和同事共享规则
- 分享：「导入 / 分享」→「分享给同事」→ 导出规则包 .yaml，发给同事（「全部规则」会带上测试用例和数据源配置，可勾选附带埋点字典 + 文档）。
  勾选「附带数据源样本」会带上规则用到的接口 JSON 和 3 MB 以内的数据库，同事没连手机也能先试。
- 导入：「导入 / 分享」→「导入同事的规则」→ 选择 .yaml，逐条预览：
  新增的默认导入；和你不同的默认保留你的，可改成「用对方的覆盖」；字典可以「合并」。
  已有的数据源默认不会被覆盖；选择覆盖时，你原来的会进历史记录，随时能切回。
- 合并后再「导出全部规则」，就是一份新的总规则包。建议团队指定一人维护「团队总规则.yaml」。

四、先试一下
- 包里附带「示例规则包（含数据源样本）.yaml」，导入后就能在「点位规则」「数据源」「测试用例」里看到示例。

五、推荐使用顺序
1. 数据源：实时抓接口 JSON、从手机拉数据库（需要时再建「合并 / 兜底 JSON」）。
2. 测试用例：新建用例，把要测的点位加进来（可以先不写规则）；「看操作」的人工确认字段（如 source）可用「批量设置」一次勾选；
   点位右侧复制按钮复制后，到其他用例按 Ctrl+V 粘贴；没保存就离开也会自动暂存草稿，回来接着改。
3. 在用例上「绑定数据源」，再点「复制整组 AI 提示词」，AI 只会看到这组点位相关的数据源。
4. 要查数据库的字段：在字段规则的「数据库」页用「SQL 向导」点出示例 SQL，或打开「数据库浏览器」看表、查表后一键填回。
5. 实时调试选上用例：左侧默认只看本用例点位（没触发的也列出来，方便对照手机操作），重复上报自动合并。

六、常见问题与报错排查
- 杀毒软件拦截：exe 是 PyInstaller 打包的 Python 程序，个别杀软会误报，加入信任即可。
- 端口被占用：默认使用 8686，被占用会自动顺延到 8687、8688…。
- 浏览器没自动打开：再次双击「埋点小岛.exe」会自动跳转到正在运行的地址，或手动访问 http://127.0.0.1:8686/ 。
- 报错日志在哪里看：
  1) 网页已打开时：点击右上角「运行日志」（接口 500 报错时右下角提示条也可一键点「查看日志」）；
  2) 启动阶段就出错时：会自动弹出 Windows 提示框，并将完整错误写入「埋点小岛数据\reports\server.log」。
