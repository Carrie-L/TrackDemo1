日志模板

不同模块日志格式不一样时，先选一个模板，再微调正则。
怎么做
  1. 先在右上角选择最接近你们日志的模板。当前默认支持 Event: id ... data。
  2. 如果模板不完全一样，只改 lineRegex。正则里必须有 ?P<event_id> 分组。
  3. 如果日志是 ClassName(a=1,b=2)，通常只要抓到 data 就够；脚本会自动解析括号里的参数。
  4. 如果日志直接打印 params=a=1,b=2，就把参数段抓到 params 分组。

候选记录 caseGroups

保证同一条日志的字段来自同一组业务数据，比如 res + cards + items。
怎么做
  1. 把一条业务数据拆成几层 alias。当前例子是 res -> cards -> items。
  2. 第一层如果想在整份 JSON 里找数组名，就填 findListKey，例如 alias=res、findListKey=res。
  3. 后续层级从上一层往下找，填 from 和 path，例如 from=res、path=body.cards。
  4. findListKey 和 from/path 是二选一。面板会自动清掉冲突项。

默认字段 fields

左边填 Logcat 字段名，右边填 JSON 路径。
怎么做
  1. 左列填 Logcat 参数名，例如 resID、operationCardId。
  2. 右列填 JSON 路径，第一段必须引用 caseGroups 里的 alias，例如 res.id、cards.cardId。
  3. 如果所有事件都校验同一批字段，只填这里就可以。
  4. 如果某些事件字段不同，到下面的 fieldsByEventId 单独配置。

按事件覆盖 fieldsByEventId

事件字段可以合并默认字段，也可以完全覆盖默认字段。
怎么做
  1. 点击“添加事件配置”，先把 eventId_1 改成真实事件 ID。
  2. 推荐使用“合并默认字段”：公共字段放在上面的 fields，每个事件这里只填差异字段。
  3. 如果选择“覆盖默认字段”，该事件不会继承公共字段，必须把要校验的字段全部写全。
  4. 再点该事件里的“添加字段”，逐行填写这个事件的差异字段或完整字段。
  5. 旁边的“0 个字段”只是统计，不需要填。它会随着字段行数量自动变化。

日志过滤 lineFilters

同一个 eventId 被其它日志打印时，用类名或关键词过滤。
怎么做
  1. 一般优先配置“按事件包含”，用类名锁住真正的上报日志，例如 88860004086008: MinePageCardClickEvent\(。
  2. 如果某些调试日志也打印同一个 eventId，把它写进“按事件排除”。
  3. 全局包含/排除会影响所有事件，只有确定整页都适用时再填。
  4. 被过滤掉的日志会计入报告里的 skippedByFilter，不会污染 PASS/FAIL。
按事件过滤格式：每行写 eventId: 正则。同一个 eventId 可以写多行。正则里的左括号建议写成 \(。

值别名 valueAliases

例如日志 cardType=1，但 JSON 是 large_normal。
怎么做
  1. 只有日志值和 JSON 值业务等价但字面不同的时候才填。
  2. 例子：字段名 cardType，日志值 1，JSON 等价值 large_normal。
  3. 多个 JSON 等价值用英文逗号分隔，例如 large_normal, large_big。
  4. 如果要求严格相等，就不要添加别名。
